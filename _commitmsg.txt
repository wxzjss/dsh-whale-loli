0.9.4: apply must never throw, or the daemon fiber never leaves Pending

The settings panel kept showing "远程方法 whale-affinity.status 未挂载" even
after 0.9.3 (which fixed the impossible inject). The on-disk trace showed
inProps=true propsType="service" selfLookupLoose=true selfLookup=false
myFiberState=1: the service WAS provided, but strict lookup hid it.

cordis ReflectService._getImpl:
    if (strict && impl.fiber.state !== 2) return;   // 1=Pending, 2=Active

dsh-api-gateway resolveSrcDescriptor (lib/index.js:1234) looks the service up
with the strict form, so a Pending provider makes the gateway skip the row and
throw gateway/invocation-unavailable.

A plain cordis Context settles 1 -> 2 and strict becomes true on its own
(measured: apply sees state 1 with loose=true), so nothing needs
re-providing. The only way to stay at 1 is _reload() catching a throw:

    catch (reason) { this.ctx.logger.error(reason); this._runner.epoch = INACTIVE; }

i.e. any exception inside apply parks the fiber in Pending forever, and the
error only reaches logger. So apply() now swallows everything: provide is
wrapped in try/catch and the whole ctx.effect() call is wrapped too. Failures
are traced to disk instead of thrown.

Also:
- switch registration to ctx.reflect.provide, which is what cordis' own
  Service constructor uses (self.ctx.reflect.provide(name, self, ...)).
- compare the status-event fiber by uid, not identity: cordis emits on the
  parent context (this.context.emit), not the ctx handed to apply.
- new verify-daemon-service.mjs runs a real cordis Context end to end and
  asserts strict visibility, fiber state 2, the typertRemote binding, and the
  counter-case that a throwing apply is invisible to the gateway.
- wire it into release.yml next to verify-daemon-inject.mjs.

Also: the daughter preset body now states plainly that it is derived from the
live-persona preset (same role-card structure), per the requested direction.
